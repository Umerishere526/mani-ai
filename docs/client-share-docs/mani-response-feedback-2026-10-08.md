# Client feedback on Mani's replies, 2026-10-08

Three styles (Directive, Supportive, Reflective), one conversation: a decision between a new job and staying. Transcribed word for word as muhammad received it. The transcripts came from a build before scope features 15 and 17.

1. Repetitive and Unnatural Mirroring
-> USER SAID: I'm facing an important decision, and I keep going back and forth. Every time I think I've made up my mind, I start questioning myself again. I'm frustrated because I don't understand why I can't just decide.
-> MANI: "The frustration of questioning yourself again just when you thought you’d decided is clear."
-> Better response: "You've been going back and forth, and neither choice feels quite right yet. What's the decision you're trying to make?"

2. Repetition and Premature Narrowing
-> MANI: "You’re afraid of choosing wrong when there are good reasons for both options. What feels most uncertain about what might happen if you accept the new job?"
-> Better response: "What's making the new opportunity appealing, and what's making you consider staying?"
This explores both sides without repeating the user's fear or prematurely focusing on one option.

3. Excessive Recapping Before Framework
MANI repeats nearly every detail the user has already provided, then adds a lengthy explanation about going through questions.
The transition feels scripted rather than conversational.

4. Unnatural and Repetitive Mirroring
-> User said: "I'm facing an important decision, and I keep going back and forth. Every time I think I've made up my mind, I start questioning myself again. I'm frustrated because I don't understand why I can't just decide."
-> MANI responded: "That repeated second-guessing sounds frustrating, especially when you feel close to deciding. What part of this choice leaves you feeling most unsure?"
-> What is not working: MANI repeats the user's frustration and second-guessing rather than responding naturally. It also asks what part of the choice feels uncertain before understanding what decision the user is facing.
-> Better Supportive response: "Making a decision can be difficult when you keep questioning yourself. What's the decision you're facing?"
-> Important: Mirroring should confirm understanding when needed, not simply restate the user's words or emotions.

5. Abrupt Framework Transition
-> User said: "I'm trying to decide whether to accept a new job opportunity or stay where I am. There are good reasons for both, and I'm afraid of making the wrong choice."
MANI responded: "Having good reasons to take the new job and to stay, while fearing you’ll choose wrong, sounds frustrating; there are some questions we could go through together."
-> What is not working: The issue is not necessarily that the framework came too soon. It is that MANI moved into it too abruptly.
-> There are three important distinctions:
1. Before the framework: MANI needs to understand the nature of the problem, not investigate every detail.
2. Introducing the framework: MANI should make a natural transition, explain briefly how the framework could help, and allow the user to choose.
3. Inside the framework: MANI should build on what the user already shared, without asking for the same information again.

The Direct conversation exposed an important distinction. MANI asked about the decision, then asked about the competing considerations. That was natural conversation. The Supportive version skipped that second question and went directly to the framework.

We previously discussed approximately four or five exchanges before introducing a framework, but I do not want that to become a fixed rule.

MANI should recognize when it understands the issue sufficiently and when a framework invitation would feel natural.

My concern is that if MANI spends too much time asking questions before the framework, the framework will simply repeat the same information.

The conversation before the framework should establish what the user is struggling with. The framework should help the user work through it.

The goal is not to delay the framework. It is to avoid making the user feel rushed into one while also preventing unnecessary repetition.

Overall Feedback
The Supportive style is gentler than Direct, but the same underlying problems remain: repetitive mirroring, unnatural phrasing, and mechanical transitions.

The framework timing needs careful attention. We should not introduce a rigid number of conversational exchanges because that could create unnecessary questions and repetition.

MANI needs to understand the user's problem sufficiently to recognize when a framework would be helpful. It should then introduce the framework naturally, without rushing the user or repeating questions that belong inside the framework.

The principle is simple: Understand the problem, introduce the framework naturally, and use what the user has already shared. Do not make the user explain the same situation twice.

-> What could improve: The opening sentence repeats what the user has already expressed. The reflective question itself is strong and should remain.
-> Better response: "What would making the wrong choice mean to you?”
This encourages reflection while allowing MANI to understand both sides of the decision.

8. Framework Cadence and Transition
-> User said: "The new job offers better pay and more responsibility, but I've been at my current company for years. I know the people, I'm comfortable there, and I'm worried I might regret leaving."
-> MANI responded: "You’re weighing better pay and more responsibility against the familiarity of your current company, and worrying you might regret leaving; there are some questions we could go through together."
-> What is not working: MANI again summarizes information the user has just provided rather than making a natural transition into the framework.

However, the cadence in Reflective was better than Supportive.

In Direct, MANI asked about the decision and then explored the competing considerations before offering a framework. This was a reasonable conversational progression.

In Supportive, MANI offered the framework immediately after learning the decision involved two jobs. The transition felt abrupt.

In Reflective, MANI allowed another exchange before offering the framework. This felt less rushed, although the question about what making the wrong choice would mean was more abstract than necessary.

The Direct conversation had the strongest progression, but none of the three styles had a sufficiently natural framework transition.

3. Inside the framework: MANI should build on what the user has already shared without asking for the same information again.
