MANI Chat Review: What Worked and What Didn't

My overall assessment: MANI is still too repetitive, too reflective, and too slow to make progress in Directive mode.It understands much of what the user says, but it does not know when to stop summarizing and start helping.

Your criticism is justified. By the third response, I would expect MANI to have moved beyond repeating the complaint.

What MANI got right

1. It recognized the anger. MANI understood that the user was upset about being blamed for the team's workload.

2. It identified the larger pattern. MANI recognized that this was not an isolated incident. The same problem happens every November despite repeated warnings throughout the year.

3. It remained calm when challenged. When the user questioned the framework, MANI did not become defensive.

4. It eventually identified the immediate event correctly. The activating event was overhearing the team complain, not the recurring November workload problem.

These are positives, but they do not outweigh the conversational problems.

What MANI got wrong

1. The mirroring is excessive

Look at these three responses:

Response 1:

The part that feels unfair is that they’re blaming you for the year-end crunch...

Response 2:

The anger is about both the blame and the way they’re telling the story...

Response 3:

You’ve warned them throughout the year, but the same complaint comes back in November...

All three responses essentially communicate the same thing. The user already explained the problem clearly. MANI keeps giving that information back to them.

After one brief acknowledgment, MANI should ask a useful question, introduce a new perspective, or help the user decide what to do. Directive mode should not require the user to repeat themselves before receiving meaningful help.

2. MANI keeps asking questions it already knows the answers to

MANI asks:

Is the anger mostly about them leaving out their role in the backlog, or about them making you look like the cause?

The user explains that both are upsetting.

MANI then asks:

Does that fit?

This adds nothing. The user has already clarified the issue. MANI should use that information rather than ask for another confirmation. This is exactly the problem we identified yesterday. MANI is listening, but it is not progressing.

3. MANI is too quick to agree with the user's interpretation

MANI says:

That would piss me off too.

I would change this. MANI can acknowledge the user's anger without immediately agreeing with their assessment of the team. There is an important difference between understanding someone's frustration and accepting their interpretation as fact.

A stronger response would be:

I can understand why hearing that upset you, especially when you've spent months warning the team about deadlines.

That acknowledges the emotion.

4. MANI selected a framework too quickly, and possibly the wrong one

This is one of the biggest problems in the conversation. The user is a leader dealing with frustration, accountability, and a recurring performance problem.

MANI introduces ABCDE to examine the belief that the team is blaming the leader. But the user has not demonstrated that their belief is irrational, inaccurate, or in need of reframing.

There may be a genuine management problem that requires a practical response. MANI should have explored what the user needed before selecting a framework.

For example:

This has become a recurring accountability problem. Are you more concerned about how to address the team now, or how to prevent this from happening again?

That question would move the conversation forward.

5. The framework introduction repeats itself

MANI says:

We can use ABCDE to look at that belief...

Then immediately says:

There's a framework called ABCDE that helps you look at the belief...

This is unnecessary duplication within the same response. One short explanation would be sufficient. It also makes the conversation sound scripted rather than natural.

6. Has the ABCDE framework actually been updated?

Based on this conversation, I do not see evidence that the updated framework is working as intended.

Or is this an updated version it sounded like the old one where it didn’t allow me to

1. Create a real conversation within each step. MANI should explore what the user says, ask thoughtful follow-up questions when needed, and help the person understand something they may not have recognized.

2. Allow meaningful back-and-forth. A step may take several exchanges. MANI should not automatically move to the next letter because the user answered one question.

3. Use what the user has already shared. MANI should remember what it knows without repeatedly asking for confirmation or making the user explain it again.

4. Help the user reach a meaningful realization. The purpose is not to complete five letters. It is to help the user examine their thinking and arrive at a different understanding when appropriate.

5. Move forward when the conversation is ready. MANI should recognize when a step has been meaningfully explored, rather than following a fixed question-and-answer script.

What happened in this test?

MANI said: A is for Activating Event. The situation is that every November, despite your reminders and preparation, they say you pile on too much work. Is that the pattern you want to explore?

The only answer is YES.

The updated ABCDE was designed to replace the mechanical question, answer, confirm, next-step process with a natural, thoughtful conversation within each stage.

MANI should use what it already knows, explore what matters, allow meaningful back-and-forth, and help the user gain insight before progressing. The framework still has five stages, but the user should experience a conversation, not an interview.

And this is the critical distinction: We wanted MANI to become more conversational, not more repetitive. A deeper conversation does not mean longer summaries or more mirroring. It means asking better questions, recognizing what matters, and contributing something useful.

That is what this MANI test failed to demonstrate.
