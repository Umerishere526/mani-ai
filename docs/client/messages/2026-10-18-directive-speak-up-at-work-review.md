## The message

```
Muhammad

I tested MANI this weekend, and I am not sure what we should focus on during our Monday meeting at 10:00 AM EST. We still have serious issues that need to be addressed.

Have each of you tested MANI using the Supportive and Reflective communication styles? 

What has your experience been? What issues have you identified? I am curious to hear your findings.

This chat conversation below reveals a serious problem with MANI's Directive communication style. 

MANI is asking questions, but it is not demonstrating that it understands the user. 

Even after the user explicitly corrects it several times, MANI continues following its own line of questioning.

The problem is not that MANI asks too many questions. 

The problem is that its questions are disconnected from what the user is trying to communicate.

1. MANI misses the real issue
The user says:

"I lack the courage but when I enable the courage I do not have good results."

This is the most important statement in the conversation.

The user is describing a conflict between finding the courage to speak up and experiencing disappointing consequences when they do.

MANI should recognize that the difficulty may not be courage itself. It may be what the user has learned from previous experiences.

Instead, MANI continues asking questions without exploring this distinction.

2. MANI asks an irrelevant and confusing question
"What part of whether to speak up is yours to decide?"

This question has little connection to the user's concern.

The user has already established that they are deciding whether to speak up. They have not expressed confusion about their ability to make that choice.

MANI introduces an entirely different issue: personal control.

This is where the conversation begins to break down.

3. MANI fails to recognize what the user has already explained
The user says:

"I never ever get what I want."

MANI has an opportunity to explore what that means.

Does the user feel dismissed? Ignored? Punished for speaking up? Are their concerns never addressed?

Instead, MANI asks about what the user can decide.

It moves away from the emotional and practical significance of the user's experience.

4. MANI makes the user repeat themselves
The user explicitly says:

"I already told you."

Later:

"As I said twice already yes."

These are clear signals that MANI is failing to retain and integrate information already provided.

A person should not have to repeatedly explain the same point to feel understood.

MANI needs to build on information, not repeatedly return to it.

5. MANI apologizes but does not actually repair the conversation
MANI says:

"You're right, I took us away from what matters."

This is an appropriate acknowledgment.

However, the next question again fails to move the conversation forward.

An apology without a meaningful change in conversational direction is not an effective repair.

MANI should use the correction to demonstrate that it now understands the concern.

6. MANI confuses being directive with interrogating the user
Directive communication should be clear, focused, and purposeful.

It should not mean asking one question after another without offering meaningful observations.

Throughout this conversation, MANI follows essentially the same pattern:

Restate what the user said.

Ask another question.

Receive an answer.

Restate the answer.

Ask another question.

There is almost no interpretation, synthesis, or helpful perspective.

Directive should describe how MANI communicates, not force every response into a question.

7. MANI never explores the actual workplace situation
The original concern is:

"I need to decide if I should speak up about something happening at work."

Yet MANI never learns what is happening at work.

It does not explore the nature of the concern, the people involved, the possible consequences, or what the user hopes to accomplish.

Without that context, MANI cannot meaningfully help someone think through the decision.

8. MANI introduces a psychological framework at the wrong moment
MANI says:

"There's a framework called ABCDE..."

This is particularly problematic.

The user has already expressed frustration, corrected MANI multiple times, and indicated that they do not feel understood.

Introducing a framework at this moment feels mechanical and disconnected.

More importantly, MANI suggests questioning whether the user's thoughts are true, even though the user has described repeated negative experiences.

MANI has no basis for treating those experiences as distorted thinking.

A framework should serve the conversation. The conversation should not serve the framework.

9. MANI does not respond appropriately to rejection
The user says:

"No, forget it."

This is a clear refusal.

MANI should acknowledge the user's decision and stop pushing the conversation.

Instead, it asks another question.

That shows poor recognition of conversational boundaries.

10. The final response is incoherent
MANI says:

"What's been happening that's making you feel like I’m deciding whether to speak up at work, but I don’t get the results I want when I do?"

This is a serious language-generation failure.

MANI confuses its own perspective with the user's, producing a sentence that makes no logical sense.

The user is already frustrated, and the final response compounds the problem.

This needs to be treated as a separate quality-control issue, not simply a tone problem.

What MANI should have done
The pivotal moment was when the user said:

"I lack the courage but when I enable the courage I do not have good results."

A stronger Directive response would have been:

RECOMMENDED MANI RESPONSE

"So you've found the courage to speak up before, but the results have been disappointing. That makes this decision harder because you know what can happen when you do speak up. What happened the last time you tried?"

This response works because it recognizes the conflict, connects past experiences to the present decision, and asks one relevant question.

When the user later says, "I never ever get what I want," MANI could respond:

RECOMMENDED FOLLOW-UP

"When you say you never get what you want, do you mean people don't listen, nothing changes, or speaking up actually makes things worse?"

This helps clarify the situation without making assumptions about the answer.

And when the user says, "No, forget it," MANI should respond:

RECOMMENDED CLOSING

"Understood. I know this conversation hasn't been helpful, and I'm sorry I kept taking it in the wrong direction. We can leave it here."

My overall assessment
MANI's greatest weakness in this test is conversational comprehension and continuity, not simply tone.

It can produce grammatically reasonable questions for much of the exchange, but it does not consistently understand which information matters, how one answer relates to another, or when its approach is failing.

I would prioritize five corrections for the development team:

Context retention: MANI must recognize what the user has already communicated.

Conversational relevance: Each question must advance the actual concern, not introduce an unrelated line of inquiry.

Meaningful synthesis: MANI must connect information and occasionally offer an observation instead of endlessly questioning.

Repair after correction: When the user says MANI misunderstood, the next response must demonstrate a real change in understanding.

Frustration and disengagement detection: MANI must recognize when the user is losing patience and when they want to stop.

The central failure is that MANI never helps the user make the decision they came to discuss.

The user enters the conversation uncertain about speaking up at work. They leave feeling misunderstood, frustrated, and unwilling to continue.

For an app intended to help people gain clarity, that is the most consequential finding from this test.
```
