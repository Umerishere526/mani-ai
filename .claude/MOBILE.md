# mobile — Expo

Expo SDK 57, expo-router, React Native 0.86.3, React 19.2.3, NativeWind v5 (preview), TypeScript 6.

**Expo has changed substantially in SDK 57.** Read the exact versioned docs at https://docs.expo.dev/versions/v57.0.0/ before writing code against an Expo API. Do not rely on remembered patterns from older SDKs, and do not copy snippets that haven't been checked against v57.

Coding standards for this app live in the `expo-react-native` skill (`.claude/skills/expo-react-native/`) — navigation, styling, lists, platform differences, and the SDK 57 APIs that replaced older ones.

Version control is the repo-root git repository, shared with `web/` and `backend/`. Run `git` from the root, not from `mobile/`.

## Commands

```bash
cd mobile
npx expo start           # dev server; press i / a to open a simulator
npm run ios              # or: npm run android, npm run web
npm run lint             # expo lint
```

`npm run reset-project` is listed in `package.json` but **broken** — it runs `node ./scripts/reset-project.js` and `scripts/` does not exist. Either delete the script entry or restore the file; don't just run it and wonder why it fails.

## Layout

- Routes live in `src/app/` (expo-router, file-based). Root layout: `src/app/_layout.tsx`.
- `src/app/_layout.tsx` imports `../global.css` — that import is what loads Tailwind. Keep it.
- Path aliases: `@/*` → `src/*`, `@/assets/*` → `assets/*`.
- `typedRoutes` and `reactCompiler` are both enabled under `experiments` in `app.json`.

Shared code lives alongside `app/`, not inside it — anything in `src/app/` becomes a route:

```
mobile/src/
├── app/                    # routes only
├── components/shared/      # reusable UI
├── hooks/                  # custom hooks, max 80 lines
├── lib/utils/              # cn() and other helpers
├── types/                  # shared types
└── dictionaries/           # user-facing strings
```

Project rules — 150-line components, optional chaining, reusability, dictionaries — are enforced via the `expo-react-native` skill.

## Styling — NativeWind v5

Styling is `className`-based and **working**. Use Tailwind classes, not `StyleSheet.create`, for new components.

The wiring, for reference:

- `metro.config.js` wraps the Expo config in `withNativewind` from `nativewind/metro`.
- `src/global.css` imports `tailwindcss/theme.css`, `tailwindcss/preflight.css`, `tailwindcss/utilities.css`, and `nativewind/theme`.
- `nativewind-env.d.ts` is generated by `react-native-css`. **Do not edit it**; it is committed on purpose and listed in `tsconfig.json`.
- `postcss.config.mjs` uses `@tailwindcss/postcss` (Tailwind v4).

There is no `tailwind.config.js` — NativeWind v5 discovers sources itself and Tailwind v4 is CSS-first. Configure theme tokens in `src/global.css`.

### Version pins that matter

- `nativewind` is on `^5.0.0-preview.4` — a **preview** release. v5 docs and v4 docs differ; make sure you are reading v5 material, and expect occasional breakage on upgrade.
- `react-native-worklets` is a required peer of Reanimated 4 — do not remove it.
- `overrides.lightningcss` is pinned to `1.30.1`; `allowScripts` permits postinstall for nativewind, react-native-css, reanimated, and safe-area-context. Both exist to make the install work — don't strip them.
- TypeScript is `~6.0.3`, ahead of web's v5.

## Conventions

- Prefer Expo modules already installed (`expo-image`, `expo-font`, `expo-symbols`, `expo-glass-effect`, `expo-web-browser`) over adding new third-party equivalents.
- Use `expo-router`'s `<Link>` and typed route helpers rather than imperative navigation where possible — `typedRoutes` gives compile-time route checking.
